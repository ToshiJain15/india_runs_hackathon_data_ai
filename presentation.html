Problem Statement : Rank top-100 candidates from 100K pool for Senior AI Engineer JD
Solution Overview
What is your proposed solution?
  • A rule-based, multi-factor weighted scoring engine decomposing candidate–JD fit into 5 independent dimensions with transparent, recruiter-adjustable weights.
  • High Scale & Zero Cost: No LLMs, no external APIs, no GPU. Scores 100,000 candidates in ~50 seconds on a single CPU core using <500MB RAM.
  • Market-Ready Product: Django + PostgreSQL + Docker + WhiteNoise + CSRF protection. Production-deployable to any cloud provider with a single docker run command.
What differentiates this from traditional candidate matching systems?
  • Dynamic JD Parser: Paste any raw job description — the engine auto-extracts skills, experience range, and role title. No manual configuration required for new roles.
  • Prodigy-Aware Logic: PhD / Master's candidates with 0 years of experience bypass the junior penalty — the system recognizes academic excellence as a substitute for tenure.
  • Honeypot Disqualification Gate: 4 physical-impossibility checks catch keyword stuffers (expert-zero-duration, YOE gap, calendar mismatch) and zero them to 0.0 — unfakeable.
JD Understanding & Candidate Evaluation
How does the system understand and parse the Job Description? NEW
  • Dynamic JD Parser (parse_job_description()): Accepts raw JD text pasted by the recruiter. Uses regex + token matching to extract: required skills, experience range (e.g. "5–8 years"), and role title. Supports any role — not limited to AI/ML.
  • Synonym Resolution: A built-in SYNONYMS_MAP maps "ML" → "machine learning", "NLP" → "natural language processing", "k8s" → "kubernetes" before skill matching.
  • Fallback Safety: If the JD text is empty or too short (<50 chars), the engine falls back to the curated DEFAULT_JOB definition — zero disruption to existing workflow.
How does evaluation go beyond keyword matching?
  • Endorsement Saturation: Endorsement trust = 0.5 + 0.5 × tanh(endorsements / 20) — 5 endorsements ≠ 100 endorsements.
  • Duration Credibility: Duration trust = 0.4 + 0.6 × tanh(duration_months / 18) — 3 months "Python expert" < 3 years "Python expert".
  • Recency Decay: Career history scores decay by 1/position_index — recent jobs matter more than 10-year-old roles.
Ranking Methodology
5-Factor Weighted Scoring Architecture
Component Weight Algorithm Special Logic
Skill Match 40% Jaccard overlap + proficiency × endorsement × duration trust curves NLP/Vector DB bonus boost
Title + Career 25% Title fuzzy match + career history with recency decay (1/pos) Consulting-firm penalty (0.2×)
Experience 15% Piecewise linear, peaks at 6–8 YOE (1.0). Non-linear crush if <3 YOE PhD bypasses junior penalty
Education 10% Institution tier × degree level × CS/Math/Stats field relevance PhD = 1.0, B.Tech = 0.75
Signals 10% Location (40%) + Notice Period (30%) + Platform Activity (30%) Noida/Pune = 1.0, >90d = 0.25
Score Formula & Tie-Breaking
  • Final: 0.40×Skill + 0.25×Title + 0.15×Exp + 0.10×Edu + 0.10×Signals, multiplied by 0.6 if critically under-experienced (or 0.9 if PhD)
  • Tie-break: Secondary sort by candidate_id ascending. Top-100 scores normalized to [0.2, 1.0].
Explainability & Data Validation
Zero-hallucination, fact-grounded reasoning
  • Programmatic Reasoning (generate_reasoning()): Every ranked candidate gets a 1–2 sentence HTML explanation citing only verified profile attributes — title, YOE, specific matching skills (e.g. Pinecone, Weaviate), location, notice period, and GitHub score. No LLM = no hallucinations.
  • Recruiter Override: All 5 weight sliders are live in the dashboard. Moving a slider from 40% to 60% for Skills immediately re-renders the Scoring Architecture visualization in real-time — the judge can see exactly how the math shifts.
4-Check Honeypot Disqualification Gate

1. Expert Zero-Duration

≥3 expert skills with 0 months of duration → score = 0.0. Eliminates keyword-stuffed profiles with zero evidence.

2. YOE vs Career History Gap

Profile claims 2+ more years than cumulative career jobs total. Catches inflated experience declarations.

3. Single Job Exceeds YOE

One listed job duration is longer than the total stated years of experience. Physically impossible.

4. Calendar Date Fabrication

Listed job duration exceeds calendar months between start_date and end_date (3-month buffer). Catches date fabrication.

Technologies Used
Technologies, frameworks, and tools — and why they were chosen

Python Standard Library (Core Engine)

math, json, csv, datetime, re — zero pip installs for the core scoring engine. Executes out-of-the-box on any Python 3.8+ environment. Memoization caches for Jaccard matching and per-JD skill sets prevent redundant computation across 100K candidates.

Django 4.2 + PostgreSQL

Django provides a battle-tested ORM, CSRF middleware, admin interface, and session management. PostgreSQL support via dj-database-url enables horizontal scaling. WhiteNoise serves compressed static assets without a separate Nginx/CDN dependency.

Gunicorn + Docker

Gunicorn WSGI server replaces Django dev server for multi-threaded production load. Docker containerization ensures the system is reproducible on any cloud provider (AWS ECS, GCP Cloud Run, Azure Container Apps) with a single docker run.

Vanilla CSS + JavaScript

Zero frontend frameworks — no React, no Webpack. Lightweight, fast-loading, and maintainable. Custom range slider CSS, live Architecture bar sync via ARCH_MAP, mobile overlay, and animated progress bars all written in <200 lines of vanilla JS.
